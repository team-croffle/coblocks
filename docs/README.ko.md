# Coblocks

**2022 개정 교육과정에 맞춘 초·중·고 블록코딩 기반 알고리즘 학습 서비스.**

> 🇺🇸 [Read in English](../README.md)

Coblocks 는 알고리즘을 통해 컴퓨팅 사고력을 기르는 것을 목표로 한다. 블록을 조립하는 것에서
시작해 순서도와 의사코드를 거쳐 텍스트 코드로 넘어가고, 모든 미션은 고시된 성취기준에
매핑되어 있어 학교 현장에서 근거를 댈 수 있다.

---

## 무엇을 위한 서비스인가

블록은 수단이지 목적이 아니다. 목적은 **알고리즘**이다. 문제를 정의하고, 쪼개고, 기계가 따라올
수 있는 구조로 표현할 수 있게 되는 것이 배울 가치가 있는 것이다. 블록 편집기를 쓰는 이유는
문법이 학습 경로를 막지 않게 하기 위해서지, 블록을 끌어다 놓는 행위 자체가 목표여서가 아니다.

### 학습 경로

| 단계 | 목표 | 미션의 모습 |
| --- | --- | --- |
| 초 3~4 | 논리적 사고. 순서, 인과, "정확히 말하기". | 짧은 순차 실행, 언플러그드 성격의 추론. 이 단계는 교과 성취기준을 주장하지 않는다. |
| 초 5~6 · 중 | 기존 알고리즘과 그 밑에 있는 원리. 반복·조건·변수·순차 자료구조·함수. | 알려진 알고리즘을 읽고, 따라가고, 비교하고, 고쳐 보고, 어디서 깨지는지 찾는다. |
| 고 | 직접 알고리즘을 설계하고 평가하기. | 낯선 문제를 분해·모델링하고, 방법을 고르고, 비용을 두고 논증한다. |

### 목표 도달은 바닥이지 천장이 아니다

같은 미로를 두 프로그램이 푼다. 하나는 30번의 이동을 40개 블록으로 그대로 나열한다. 다른 하나는
반복과 분기를 써서 20개 블록으로 끝낸다. 둘 다 목표에 도달하지만, 문제의 **구조**를 찾아낸 것은
두 번째뿐이다.

이 차이가 Coblocks 가 가르치려는 것이다. 알고리즘은 단지 목표를 달성하는 데 그치지 않고
추상적이고 논리적인 원리를 가져야 한다. 구체적으로는:

- 인터프리터가 실행 단계 목록을 만들어 두므로, 실행 후 블록 수와 실행 단계 수를 모두 알 수 있고
  학습자에게 되돌려 줄 수 있다.
- 미션은 기준 풀이를 염두에 두고 출제한다. 따라서 "40개 블록으로 도달했는데, 20개로도 된다"는
  질문을 서비스가 던질 수 있다.
- 학년군에 따라 이 비중을 의도적으로 다르게 둔다. 초등에서는 도달 자체가 학습이고, 중학교부터는
  풀이의 *모양*이 학습이다.

구조에 대한 피드백(블록 수·제어구조 사용을 플레이어에서 점수로 보여 주는 것)은 설계된 동작이지만
**아직 구현되지 않았다**. 현재 채점은 서버에서 계산하는 성공/실패뿐이다.

### 교육과정 매핑

| 학교급 | 교과 | 시수 | 코드 형식 |
| --- | --- | --- | --- |
| 초 3~4 | (해당 없음) | — | 교과 외 준비 단계 |
| 초 5~6 | 실과 '디지털 사회와 인공지능' | 34시간 | `[6실05-XX]` |
| 중 1~3 | 정보 | 68시간 | `[9정0X-XX]` |
| 고 | 정보(일반선택) | 학교 편성 | `[12정0X-XX]` |

성취기준 원문은 교육부 고시 그대로 저장하며 요약하거나 다듬지 않고, 미션 하나에는 성취기준 코드를
많아야 하나만 붙인다. 초 3~4 미션은 없는 성취기준을 주장하는 대신 아예 붙이지 않는다.

### 개념 축

순차, 반복, 조건, 변수·데이터, 함수·추상화, 자료구조, 알고리즘 설계, 인공지능 — 8개 개념이 각각
고정된 색 토큰과 1:1로 대응한다. 미션에는 대표 개념 하나만 붙인다. 색이 두 개면 학생이 색으로
개념을 읽어내는 학습 장치가 무너진다.

## 스택

| 영역 | 선택 |
| --- | --- |
| 프론트 | React 19 + React Compiler · Vite · TypeScript 6 · TanStack Router/Query · Zustand · Tailwind v4 |
| API | NestJS · Drizzle ORM · PostgreSQL 16 · JWT(Passport) · argon2 |
| 공통 | `packages/shared` — 타입, 커리큘럼 시드, 블록 인터프리터 |
| 툴링 | pnpm 워크스페이스 · oxlint · oxfmt · husky + lint-staged (ESLint/Prettier 미사용) |
| 배포 | GHCR 컨테이너 이미지(`coblocks-web`, `coblocks-api`) · compose 파일은 `docker/` |

│        ├─ lessons/       미션 조회

### 채점이 이루어지는 방식

`packages/shared` 가 블록 프로그램을 평탄한 실행 단계 목록으로 컴파일하고(`compile`) 스테이지를
따라 실행한다(`run`). 웹은 이것으로 애니메이션 미리보기를 만들고, API 는 `progress.attempt()`
에서 **같은** 함수를 호출해 그 결과로만 완료를 기록한다. 클라이언트가 보낸 성공 여부는 믿지 않는다.

## 시작하기

Node 22 이상과 pnpm 11 이 필요하다(`corepack enable` 로 고정된 버전이 잡힌다).

```bash
pnpm install
cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env

pnpm db:up        # docker compose 로 PostgreSQL 기동
pnpm db:push      # Drizzle 스키마 반영
pnpm db:seed      # 성취기준 · 미션 · 개발 계정 시드

pnpm dev          # web(:5173) + api(:3000)
```

개발 계정(비밀번호 = 아이디): `student1`, `teacher1`, `admin`.

### 명령

| 명령 | 하는 일 |
| --- | --- |
| `pnpm dev` / `dev:web` / `dev:api` | 둘 다, 또는 하나만 실행 |
| `pnpm check` | `lint` + `fmt:check` + `typecheck` — 커밋 전 반드시 통과 |
| `pnpm lint` / `lint:fix` | oxlint |
| `pnpm fmt` / `fmt:check` | oxfmt |
| `pnpm typecheck` | 워크스페이스 전체 타입 체크 |
| `pnpm --filter @coblocks/api test` | 인터프리터 테스트(vitest) |
| `pnpm db:up` / `db:push` / `db:seed` | 로컬 DB 수명주기 |

## 설계상 지켜야 할 것

리뷰에서 강제되며 우회하지 않는다:

1. **채점은 서버가 한다.** 완료 판정은 `apps/api/src/progress/progress.service.ts` 의
   `attempt()` 안에서 제출된 프로그램을 다시 실행해서만 정해진다.
2. **개인정보는 마스킹된 형태로만 나간다.** 사용자 데이터를 담는 모든 경로는
   `apps/api/src/common/masking.ts` 를 거친다. 원본 열람은 사유를 남기고 승인을 받아야 한다.
3. **감사 로그는 추가만 한다.** `audit_logs` 에 대한 UPDATE/DELETE 는 코드에서도, DB 권한에서도
   막는다.
4. **개념 색은 고정이다.** `tokens.css` 의 8개 토큰은 순서를 바꾸거나 재사용하지 않고,
   컴포넌트는 hex 대신 토큰을 쓴다.
5. **성취기준은 인용하고 요약하지 않는다.** 없는 기준이면 미션을 만들기 전에 고시 원문을 먼저
   등록한다.

## 현재 상태

아직 제품이 아니라 동작하는 스캐폴드다. 학습자 흐름(랜딩 → 로그인 → 대시보드 → 커리큘럼 →
블록 플레이어)과 관리자 6개 화면이 돌아가고, API 는 인증·미션·진도·관리자 엔드포인트를 구현했으며,
일부 화면은 API 연결 전 시드 데이터로 폴백한다. Blockly 기반 편집, canvas 스테이지 렌더러,
커스텀 블록, 학급, 코드 변환은 계획 단계이고 아직 착수하지 않았다.
